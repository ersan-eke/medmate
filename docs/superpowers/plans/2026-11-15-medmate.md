# MedMate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local, voice-first English medication companion: spoken question → red-flag check → hybrid retrieval over NHS leaflets → schema-constrained local LLM answer with validated citations → spoken answer from an animated avatar.

**Architecture:** One FastAPI app serves a no-build web page and four JSON/audio endpoints. All answer logic sits behind one function, `answer_question()`, which gets its embedder and LLM passed in, so the whole pipeline is tested without Ollama. Voice and avatar are thin layers on top: an audio file in, an audio file out.

**Tech Stack:** Python 3.12 (uv), FastAPI, uvicorn, pydantic v2, `ollama`, `rank_bm25`, `numpy`, `faster-whisper`, `kokoro` (+ `soundfile`), `matplotlib` (eval charts), `pytest`, `httpx` (TestClient). Frontend: plain HTML/CSS/ES modules, tested with `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-15-medication-companion-design.md`

## Global Constraints

- English only. No user question or answer text may be sent to any third-party service; everything runs on the demo laptop with Wi-Fi off.
- Python pinned to **3.12** via `uv` (`.python-version`): the system Python is 3.15, too new for `kokoro`/`faster-whisper` wheels. Spec says "3.11+"; 3.12 satisfies it.
- Frontend: no framework, no build step, served by FastAPI at `http://localhost:8000`.
- Red-flag check runs **before** retrieval and the LLM, and a hit never calls the LLM. Over-trigger on symptoms: "is chest pain a side effect of amlodipine?" **does** fire.
- Retrieval keeps the **top 4** chunks. Fusion is Reciprocal Rank Fusion.
- Answers are single-turn and non-streaming. No chat history is sent.
- Medicine list lives in `localStorage` only; no database, no accounts.
- Emergency number: **999**.
- UI footer and README carry: `Information from the NHS website, licensed under the Open Government Licence v3.0. Not medical advice. In an emergency call 999.`
- Every leaflet keeps its source URL, retrieval date and licence line. No BNF-derived text.
- TTS chain: Kokoro → (optional Piper) → macOS `say`. No cloud TTS, no browser `speechSynthesis`.
- Feature freeze **Wed 18 Nov 12:00**; Canvas submission before **Wed 18 Nov 23:59**.

## Test seams

The spec's behaviour is tested at **one high seam**: `POST /api/chat` through FastAPI's `TestClient`, on an app built by `create_app(index, embed, generate)` with a fake embedder and a scripted fake LLM. Below that, only the three units the spec names get direct tests: `safety` (one test per pattern plus near-misses), `retrieval` (hybrid vs BM25 vs vector, boost), and `llm` validation (citations, numbers). Speech gets a fallback-order test with fake engines and one slow real round-trip test (`say` → Whisper). Frontend pure logic gets `node --test`; the rest of the UI is verified by a written manual checklist.

## Review Focus

1. **Ollama not running or model not pulled.** `/api/chat` must return the `FALLBACK` answer with HTTP 200, never a 500, so the page and avatar keep working. → Task 5 test `test_llm_unreachable_returns_fallback`.
2. **Red-flag phrasing variants**: case, punctuation, `can't` / `cant` / `cannot`, and the exact demo line "Now my chest feels tight." must all fire. → Task 1 tests.
3. **Empty or junk input**: a blank typed question or an empty Whisper transcript must give `NOT_HEARD`, not an LLM call or a 422 shown as an error. → Task 5 `test_blank_question_not_heard`, Task 8 `test_transcribe_empty_audio`.
4. **Corrupt or hostile medicine list**: unknown names, odd case, 50 entries, or broken `localStorage` JSON. The server keeps only known medicines (case-insensitive, max 20) and the page resets a corrupt store instead of crashing. → Task 5 `test_medicine_list_sanitised`, Task 9 `loadMedicines` tests.
5. **A dose number not in the cited passage** (anti-goal 1). A number in the answer that appears in neither the cited chunks nor the user's own doses (and isn't `999`) makes the answer invalid → retry → `FALLBACK`. → Task 4 `test_uncited_number_rejected`.

## Release gates (the real system, not fakes)

The fake-LLM tests prove the pipeline's logic. They can't prove the live demo works: a real model may cite wrongly, Whisper may mishear the red-flag line, or Kokoro/Whisper may try to download weights at the venue. These gates run on the demo laptop with the real index, models and audio, via `scripts/preflight.sh` (Task 12). They must pass at feature freeze **and again on demo morning**. A failing gate gets fixed, or reported honestly in the slides; the threshold is never quietly lowered.

1. **Demo script, end to end** (`tests/test_demo_live.py`, `slow`, Task 11). Each spec §7 question with its §7 medicine list goes through `default_app()`. Step 3 → `answer`, with a source `metformin#how-and-when-to-take-it*` and a metformin side-effects source. Step 4 (turmeric) → `not_covered`, no sources. Step 5 → `emergency`, `llm_called false`.
2. **Spoken red flag**: `say_engine()("Now my chest feels tight.")` → `/api/transcribe` → `/api/chat` → `emergency`. The same for "my face is drooping on one side". Whisper's spelling of what it hears must still trip the rules.
3. **Offline cold start**: with Wi-Fi off and `HF_HUB_OFFLINE=1`, the server starts and one transcribe, one tts and one chat succeed. This proves every model weight is cached locally.
4. **First answer is fast**: the first `/api/chat` after startup answers in ≤ 10 s, because `default_app` warms every model at startup.
5. **Eval gates** (Task 11): red-flag recall = 1.0; correct-refusal rate ≥ 0.9; hybrid hit@4 ≥ both BM25-only and vector-only.

### Task 3: Hybrid retrieval

**Files:**
- Create: `backend/retrieval.py`, `tests/conftest.py`, `tests/test_retrieval.py`

**Interfaces:**
- Consumes: `Index`, `Chunk`, `Embed` from Task 2.
- Produces:
  - `Hit` (frozen dataclass): `chunk: Chunk, score: float`.
  - `Retrieval` (frozen dataclass): `hits: list[Hit], max_similarity: float`.
  - `class Retriever: __init__(self, index: Index, embed: Embed)`, which builds `BM25Okapi` once over lower-cased word tokens; `search(self, question: str, medicines: list[str], k: int = 4, mode: Literal["hybrid", "bm25", "vector"] = "hybrid") -> Retrieval`.
  - Constants: `RRF_K = 60`, `BOOST = 1.5`, `MIN_SIMILARITY = 0.45` (placeholder; Task 11 tunes it).
- `tests/conftest.py` provides `fake_embed` (hashing bag-of-words, 512 dims, L2-normalised, ignores the query/document flag) and `tiny_index` (built from `tests/fixtures/leaflets` with `fake_embed`). Tasks 4, 5 and 11 reuse both.

**Decisions:**
- RRF score = Σ over the rankers used of `1 / (RRF_K + rank)`, with each ranker's full ranking.
- **Target medicines** = KB medicines named in the question (case-insensitive whole word). If none are named and the question contains the word "my", use the user's list. Target chunks get their fused score × `BOOST`.
- **Confidence gate uses `max_similarity`**, the best raw cosine between the query vector and the returned hits. A fused RRF score is rank-based and can't express "nothing matches". This is how spec §5.2's "best fused match below a threshold" gets measured. `max_similarity` is always computed, in every mode.

### Task 4: Prompt, structured output and validation

**Files:**
- Create: `backend/llm.py`, `prompts/system.txt`, `tests/test_llm_validation.py`

**Interfaces:**
- Consumes: `Hit` from Task 3, `messages` from Task 1.
- Produces:
  - `Generate = Callable[[list[dict], dict], str]`: (chat messages, JSON schema) → raw JSON string. Raises on transport failure.
  - Pydantic `Card(summary: str, what_to_do: list[str], get_help_if: list[str])` and `LlmAnswer(in_scope: bool, covered: bool, answer: str, citations: list[str], card: Card)`. `ANSWER_SCHEMA = LlmAnswer.model_json_schema()`.
  - `build_messages(question: str, medicines: list[MedicineEntry], hits: list[Hit]) -> list[dict]`. The system prompt is read from `prompts/system.txt` (prompts must be in the submission zip). The user message lists the passages as `[<chunk id>] <Medicine> — <Section>\n<text>`, then "The user's medicines: …" (or "none listed"), then the question.
  - `validate(raw: str, sent_ids: set[str], allowed_numbers: set[str]) -> LlmAnswer | None`.
  - `ask_llm(question, medicines, hits, generate) -> LlmAnswer | None`: up to 2 attempts. Returns `None` if both are invalid or `generate` raises.
- `MedicineEntry` is defined here as a pydantic model: `name: str, dose: str = "", times: list[Literal["morning", "midday", "evening", "bedtime"]] = [], note: str = ""` (max length 100 each). Task 5 reuses it.

**Validation rules:**
- The JSON parses against `LlmAnswer`.
- If `in_scope and covered`: `citations` is non-empty and ⊆ `sent_ids`, and every number in `answer` is in `allowed_numbers`. Numbers are digit tokens (regex `\d+(?:\.\d+)?`) plus number words `one`…`twelve` and `twice`, normalised to digits (`twice` → `2`), so "take two tablets" can't slip past. `allowed_numbers` = numbers (same extraction) in the cited chunks' text + in the user's doses + `{"999"}`.
- If not `covered` or not `in_scope`: citations are ignored. The result is valid; the pipeline replaces the text.

**System prompt content** (spec §5.4): calm pharmacist persona, plain words, short sentences, older reader; answer only from the numbered passages; quote the leaflet for doses and timing; never give new dosing advice; `covered: false` if the passages don't answer it; `in_scope: false` if it's not about medicines or health; cite chunk ids exactly as given; at most 4 sentences.

**Pipeline order** (each step returns early):
1. Strip the question. Empty → `not_heard`, `NOT_HEARD`.
2. `check_red_flags` hit → `emergency`, `EMERGENCY`, `red_flag=id`, `llm_called=False`.
3. Sanitise medicines: keep entries whose name case-insensitively matches a KB medicine (renamed to the KB spelling), dedupe, first 20.
4. Retrieve. `max_similarity < MIN_SIMILARITY` → `not_covered`, `NOT_COVERED`, no sources, `llm_called=False`, card `Card(summary="This isn't covered in my leaflets.", what_to_do=["Ask your pharmacist or GP."], get_help_if=[])`.
5. `ask_llm`. `None` → `fallback`, `FALLBACK`, `llm_called=True`.
6. `in_scope` false → `off_topic`, `OFF_TOPIC`, no card. `covered` false → as step 4, but `llm_called=True`.
7. Otherwise `answer` with the LLM's text and card, and sources for the cited ids in citation order.
